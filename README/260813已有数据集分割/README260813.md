## 一、简要功能说明

### 1.1 目标

竞赛的 VAL/TEST 集不含标注，模型训练时只能靠「本地验证集」监控过拟合、选 checkpoint、早停，以及**不消耗 Codabench 每日提交额度**地离线评估。本次开发解决两个问题：

1. **分割机制升级**：把原有的「样本级随机分割」升级为「按患者/病例分组 + 分类分层」，杜绝数据泄漏、保证类别均衡，并产出含完整元信息的富验证清单。
2. **新增 predict 模块**：新增 `predict_val.py`，读取富验证清单，生成**竞赛提交格式**的预测文件，并复用现有评估代码做离线评分。

### 1.2 交付内容

| 模块 | 文件 | 说明 |
|------|------|------|
| 分割机制 | `datasets/uusivc2026_paths.py` | 新增 `derive_group_key()`、`split_entries()`、`_collect_labeled_training_entries()`，改造 `write_fixed_manifests()` |
| 配置 | `configs/stage1_seg.yaml`、`configs/stage2_cls.yaml` | `data` 段新增 `split_mode: grouped_stratified` |
| predict 模块 | `predict_val.py`（新增） | 读 `val_entries.json` → 生成提交格式 + 离线评分 |

### 1.3 核心设计思路

**单一事实来源**：把「分割」从「切 manifest 字符串」升级为「切 JSON 条目」。`split_entries()` 被训练管线与 predict 模块共用，train/val 完全一致。`write_fixed_manifests()` 仍产出 txt manifest（`train.py`/`test.py` 完全无感知、向后兼容），额外产出 `val_entries.json` + `split_summary.json`。

## 二、具体技术细节

### 2.1 分割机制

#### `derive_group_key(entry) -> str` — 患者/病例分组键推导

**关键发现**：JSON 里的 `data_partition_group` 字段**不是患者 ID**——它只有两个取值 `private_train`（私有数据）和 `public_all`（公开数据），仅标识数据分区。JSON 中也没有 `patient_id` 字段。真实患者身份只能**从文件名按任务推导**。

规则（已逐条在真实数据上验证）：

| 任务 | 文件示例 | 分组键规则 |
|------|----------|-----------|
| `ceus_seg` | `0001343561_1060.npy` | 剥末尾时间戳 → `0001343561` |
| `video_seg` | `patient0001_2CH.npy`（公开）<br>`X001.npy`（私有） | 有下划线剥视图 → `patient0001`；无则整名 |
| `image_cls` / `image_seg` | `normal_10_0.jpg`（多帧）<br>`normal_0.png`（单图） | **仅当 ≥2 个下划线**（`标签_病例_帧`）才剥帧号，否则整名即病例 |
| `ceus_cls` | `0001343561.npy` | 整名即病例（一文件一患者） |

分组键前缀 `{partition}/{organ}` 用于防止公开/私有、跨器官撞名。

#### `split_entries(entries, val_fraction, seed, mode) -> (train, val)`

| 模式 | 行为 |
|------|------|
| `random` | 样本级随机分割（复现旧行为，向后兼容） |
| `grouped` | 整组（患者/病例）只进 train 或 val，组内不拆 |
| `grouped_stratified` | 分组 + 分类任务按 `class_label_index` 分层，保证 train/val 类别均衡 |

固定 `seed` + 组键排序后 shuffle，保证可复现。

### 2.2 富验证清单

`write_fixed_manifests()` 额外产出：

- **`val_entries.json`**：验证集完整条目列表，保留 `sample_id`/`organ`/`dataset_name`/`input_path_relative`/`target_path_relative` 等全部元信息，并附加 `_root`（该条目的物理数据根，因 public/train 物理根不同）。专供 `predict_val.py` 读取。
- **`split_summary.json`**：每个 task 的 train/val 样本数、组数、类别分布，便于人工自查分割质量。

### 2.3 `predict_val.py`

单脚本三大职责（`--no-score`/`--no-zip` 开关控制）：

1. **生成提交文件（核心）**：读 `val_entries.json` → 按 `entry["task"]` 分发到 `predict.py` 的 5 个 `predict_*()` 函数。与 `predict.py` 的关键差异：`phase_root` 用 `Path(entry["_root"])`（条目来自 public/train 两个根）。分类以 `sample_id` 为 key 写 `classification.json`，分割掩码写 `output_rel(entry)` 路径。复用 `write_submission_zip()` 打包。
2. **离线评分（可选）**：复用 `test.py` 的 `build_eval_loaders()` + `evaluate_segmentation()`/`evaluate_classification()`，产出 `metrics.json`。
3. **一致性告警**：`local_val_fraction`/`split_seed` 从 config 读取。

复用清单（import 不复制）：`predict.py` 的 `load_model`/`resolve_submission_checkpoint`/`build_ceus_processor`/5 个 `predict_*`/`write_submission_zip`；`test.py` 的 `build_eval_loaders`/`evaluate_*`；`models/build_model.py` 的 `build_model`。

### 2.5 使用方法

```bash
# 生成完整验证集预测 + 离线评分（默认 stage2_cls，分类）
python predict_val.py --config configs/stage2_cls.yaml --data-root /path/to/data --device cuda

# 分割评分
python predict_val.py --config configs/stage2_cls.yaml --data-root /path/to/data --device cuda --stage stage1_seg

# 指定 checkpoint / 只生成文件不打分
python predict_val.py --checkpoint outputs/stage2_cls/best_checkpoints/best_stage2_cls_rank1.pth --no-score
```

## 三、关键发现与陷阱

1. **`data_partition_group` 不是患者 ID**：只是分区标记，患者分组必须按任务从文件名推导（见 2.1）。
2. **跨任务重叠**：`ceus_seg`(502 患者) 与 `ceus_cls`(504 患者) 共享 501 个患者。本版按任务独立分割，为已知局限（未处理）。
3. **raw `scp` 破坏换行符**：本地 `core.autocrlf=true` 让本地 git 正确处理 CRLF，但 `scp` 直接拷字节绕过 git 规范化，导致服务器 diff 爆炸。**同步代码务必走 git（`git bundle`），不要 raw scp**。
